## 一、改了什么（一句话）

把联想原厂 thermal-engine 的**降频触发温度整体提前**（CPU 43℃→38℃、GPU 44℃→41℃），
让日常刷视频时壳温不再长期顶在 40℃ 以上；**不写任何分区**，开机用 bind mount 盖两个阈值文件，删模块重启即完全复原。

| 文件 | 原厂 | 本模块 | 差异 |
|---|---|---|---|
| `/vendor/etc/thermal-engine_cpu_0.conf` | thresholds 35/43/45/47/49℃，clr 30/41/43/45/47 | thresholds 35/**38/40/42/44**℃，clr 30/**36/38/40/42** | 只改 4 行数字（两个 cluster 各 2 行） |
| `/vendor/etc/thermal-engine_gpu_0.conf` | set_point 44/46/48/50℃ | set_point **41/43/45/47**℃ | 只改 8 行数字 |

`action_info`（各档频率上限）**一字节未动**——只提前触发点，不改变每档收多狠；GPU 比 CPU 保守 2℃，是为了少伤游戏帧率。
背光限制（`thermal-engine_common_0.conf`，55℃ 才降亮度）**没有改**，避免屏幕变暗这种看得见的副作用。

## 二、两个必须记住的坑（本次各花了一次重启才发现）

1. **文件内容必须是纯 ASCII，且不要加注释。**
   第一版我在 conf 顶部写了中文说明注释，结果 thermal-engine **静默不加载**：日志只留一句
   `ss_algo_init: No SS's configured.`，CPU/GPU 一路跑到 boost 档（小核 3628800、大核 4608000）——
   **等于整机没有温控**。原厂唯一带注释的 `thermal-engine_common_0.conf` 用的是纯 ASCII 注释。
   做法改为：从本地官方包 `临时存档/c17prove/vendor_a.img` 用 7-Zip 抽出原厂件，`python` 只替换数字行，
   一个多余字符都不加（生成器 `临时存档/mk_thermal.py`，实测与原厂差异 CPU 4 行、GPU 8 行、非 ASCII 字节 0）。

2. **bind mount 会把源文件的 SELinux 标签一起带过去。**
   Magisk 装完模块里的 conf 是 `u:object_r:system_file:s0`，而 `/vendor/etc/` 原厂件是 `vendor_configs_file`；
   thermal-engine 域读不到 `system_file`，同样表现为"没加载"。修法：`post-fs-data.sh` 挂载前先
   `chcon u:object_r:vendor_configs_file:s0 "$CONF"/*.conf`。**这个失败没有任何 avc 日志可查，只能对比标签发现。**

> 顺带一条通用教训：**不要为了"让新配置生效"而 `setprop ctl.restart thermal-engine`。**
> 重启后的 daemon 不会自己接回"场景 0"（要等系统侧客户端再下发一次），于是整段开机时间没有温控、频率直接跑 boost 档。
> 正确姿势只有一个：**挂载放在 post-fs-data 阶段，然后整机重启一次**。

## 三、命令面（已执行）

```bash
# 1) 生成 conf（不猜字节，从本地官方包抽原厂件再 sed 改数字）
python 临时存档/mk_thermal.py
# 2) 打包（module.prop 必须在 zip 根）
cd 03_脚本与模块/modules/y700_thermal_tune
7z a -tzip ../../临时存档/tt.zip module.prop post-fs-data.sh service.sh confs
# 3) 安装：/data/adb 不让 root 直接 cp，必须走 magisk
adb push 临时存档/tt.zip /data/local/tmp/tt.zip
adb shell "su -c 'magisk --install-module /data/local/tmp/tt.zip'"
# 4) 重启一次生效
adb reboot
```

## 六、已知代价

- 刷视频/日常使用时大核从 4512000 降到 2880000 的时机提前 5℃，**峰值性能略降**（用户已认可该代价）。
- 游戏（和平精英 90 档、原神 45 档）到 41℃ 就会碰 GPU 第一档；若实测掉帧明显，把 GPU 段单独退回 44/46/48/50（改 `confs/thermal-engine_gpu_0.conf` 一处文件、重启即可），保留 CPU 提前量。
- 场景 5/100/200/300/400/700（游戏/充电等专用档位，走 `thermal-engine_cpu_1..7.conf`）**本次未改**；如日后要统一提前，需一并覆盖并把 `thermal_user_case.conf` 的场景切换实测清楚。
