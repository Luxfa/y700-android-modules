# v1 失败根因 + GPT 恢复研究（2026-11-23 凌晨，总管）

> 背景：v1 候选包 9008 刷入后 boot 失败（slot-unbootable:a → 掉 fastboot）；随后设备 GPT 进入无效态，firehose 一切写操作报 `invalid gpt entry number 128 entry size 128 / fail to get custom partitiont`。
> 性质：纯研究文档，不含任何设备操作。

## 一、v1 boot 失败根因（证据链闭合）

**fstab 文件系统类型不匹配 + my_* 挂载项缺失。**

| 证据 | 内容 | 出处 |
|---|---|---|
| 联想 2.5 fstab | system/system_ext/product 声明 **ext4**，无 my_* 条目 | C17拆解证据/boot/fstab.qcom_官方2.5 |
| v1 实际镜像 | system_a/system_ext_a magic = `e2e1f5e0` = **erofs** | candidate_v1 实测 xxd@0x400 |
| 供体 fstab | 6 逻辑分区 ext4/erofs 双行 + odm/my_* 22 行 | C17拆解证据/donor105/fstab.qcom_105 |
| C17 手法 | vendor_boot 整套换供体（fstab 随供体，天然匹配 erofs+my_*） | 005c 报告 |

机理：first_stage_mount 按 ext4 挂 erofs → 挂载失败 → boot 计数耗尽 → unbootable → fastboot。

**教训（总管自检）**：v1 施工时我裁定"最小改动保联想启动链"，偏离了图纸"启动链整套换供体"的 A 系条目。fstab 是启动链的一部分，保 vendor_boot 却没有同步做 fstab 适配。修复规格书已派 010 单。
