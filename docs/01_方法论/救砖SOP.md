## ⚠️ 本机血泪教训（2026-11-22 实测，必读）

1. **fastboot 必须插平板【侧边中置】USB-C 口**。底部口在 fastboot 模式下枚举为 MTP 形态（VID_17EF&PID_7FE1），fastboot 工具永远识别不到；侧边口才是标准 fastboot（VID_18D1&PID_D00D）。ADB 模式两个口都正常，极具迷惑性。
2. **驱动**：侧边口枚举出的 "Android" 设备默认无驱动。修复：`00_救生包\tools\usb_driver\`（Google usb_driver r13，已安装为 oem197.inf）；若设备管理器里出现带叹号 Android，右键→更新驱动→让我从列表选取→**取消勾选"显示兼容硬件"**→Google, Inc.→Android Bootloader Interface→警告点是。
3. fastboot 闲置可能掉线，操作要连贯；掉线就重新 `adb reboot bootloader`。
4. Bootloader_SN 读法（解锁申请用）：进 fastboot 后 `fastboot getvar all`，取 `BL_UNLOCK_SN1`+`BL_UNLOCK_SN2` 直接拼接（64位）。本机值存于 `05_备份索引/fastboot_getvar_all_20261122.txt`。
5. **EDL 退出**：进 EDL 后屏幕全黑为正常。退出=**三键同按**（电源+音量上+音量下）约10秒 PMIC 硬复位，松手后短按电源开机；单独长按电源**无效**（PBL 不轮询按键）。复位后 boot reason 显示 reboot,edl 为正常。
6. EDL 进入法：`adb reboot edl`（无损可退，前提是记住第5条的退出方法）。

## 1. 先判断设备状态

| 现象 | 判定 | 走哪条 |
|---|---|---|
| 能进 Fastboot（音量下+电源，或 `adb reboot bootloader`） | 软砖 | → 2 |
| 不能进 Fastboot，但能进 9008（设备管理器有 QDLoader 9008） | 半砖 | → 3 |
| 完全黑屏无反应 | 疑似硬砖 | → 3，失败则送售后 |

进 9008 方法：**首选 `adb reboot edl`**；按键/短接法以本机实测为准（退出务必按上文第 5 条三键同按）。

## 1.5 【新增·动手前必做】防回滚（ARB）前置检查

**联想五代侧机制是 AVB rollback index，不是欧加 ColorOS 16.0.3.501+ 的 eFuse/`xbl_config` 熔断，不要把那套说法搬过来。** 判据只需两个镜像：

1. 读本机 `boot_a` 与 `vbmeta_system_a` 的 rollback index；
2. 与**目标降级包**同名镜像的 rollback index 比对：**两个值都 ≥ 本机历史最高 ⇒ 可正常开机**；
3. 低于则**不要强刷**：社区实测"不解锁 BL 直接刷旧包 = 防回滚变砖、卡红字无法开机"，且"一旦开机就要重新 9008"。
4. 可选绕法（社区实测，**尚在本机未验证，用前先测**）：把降级包内 `boot` + `vbmeta_system` 的回滚值改成 ≥ 历史最高值再刷。
5. 官方解锁口径（社区）：解了 BL 后回滚不再阻断 —— **此条必须在我们自己机器上验证后才算数**。

## 1.6 【新增】引导文件选型排错（第一项就查这个）

- **五代** 9008 引导是 `devprg_legion-y700-5-*` **multi-image**（8E5 新处理器）；**四代** 用 `xbl_s_devprg_ns.melf`。**两者不通用。**
- 选错的表现是**"永远卡在正在发送引导"**——极易被误诊成驱动没装好或数据线问题，从而反复重装驱动白耗时间。
- ⇒ **排错顺序：先看引导文件名是不是五代 multi-image，再怀疑驱动与线材。**
- 官方线刷包的 `rawprogram` XML **存在加密**，QFIL 直接用会失败；解包后的 7z 若只给出 `contents.xml`，注意它是**芯片侧构建清单**（本机内容含 `product_name=Kaanapali.LA.1.0`、`chipid=KAANAPALI`，即 SM8850P），**不是分区刷写清单**，别拿它当 rawprogram 用。
- `lpunpack` 解 super 前必须先 `simg2img` 转 raw。

## 2. 软砖：Fastboot 路径（**只当应急，不是主路径**）

```bash
fastboot getvar all          # 先记录：确认识别、读防回滚版本
```

**为什么不作主路径**：跨大版本只走 fastboot、不刷关键分区，有"开机报 `crushdump`、最终必须 9008/QFIL 全量重刷才能恢复"的实测前科（4pda 实测）。**能用 9008 就用 9008。**

## 3. 半砖/硬砖：9008 全量回退（**主路径**）

1. 打开 9008 工具，加载**五代 multi-image 引导**（见 1.6）或本包内官方 firehose。
2. 刷写清单必须 **`rawprogram0~5` 与 `patch0~5` 成对**加载（UFS 共 6 个 LUN；**漏 LUN5 就丢 modemst/fsg 映射**）。`super` 在 LUN0（同 LUN 还有 `vbmeta_system_a`、GPT）；`boot/init_boot/vendor_boot/vbmeta/dtbo/recovery` 在 LUN4。
3. **身份分区一律不写**（`filename` 留空/跳过）：`proinfo`、`lenovolock`、`persist`、`modemst1`、`modemst2`、`fsg`、`fsc`、`keystore`、`frp`、`devinfo`、`spunvm`、`uefivarstore`。**这就是刷不丢 SN 的原因**；本项目铁律另加一条：不可逆区 `modemst1/2`、`frp`、`persist` **永不进写面**。
4. 全量刷原厂 2.5.10.055 包（**不要勾任何"保留用户数据"选项**）。
5. **首次开机前必须 wipe `userdata` + `metadata`** —— 这不是可选项：不清数据的表现是无限重启，是最高频翻车原因。
6. 刷完强制重启；仍无反应，重复一次。
7. 两次失败 → 停止折腾，见下方"字库/自库包"档，再考虑送修。

### 3.5 更深一档：分区被全部格式化时

常规 9008 包**不含序列号分区与用户数据**，表现是"**刷了会亮屏但进不去系统**"，此时需要**字库（自库）包**；SN 丢失、陀螺仪异常同理要靠刷回本机字库备份解决。⇒ 这正是 `分区备份_20261123.7z` 必须长期保命的原因。

### 3.6 官方保修口径（须知，非技术）

- 联想官方：**不支持删除系统文件或回退至旧版本系统**。
- **自行刷机（解锁 BL、Root）导致序列号错误或 TEE 损坏，不属于保修范围**；TEE 损坏用户无法自修，只能线下服务站。
- 社区有"五代出厂 TEE 损坏"讨论（是否批次问题，**官方与社区均无定论**）。
