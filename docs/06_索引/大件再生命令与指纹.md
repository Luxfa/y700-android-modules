## 二、再生命令（源包位置已核实仍在磁盘）

### 1. kernel / kernel_dtb（源：105 供体 boot.img）

> **⚠️ 11-26 19:4x 路径变更**：`06_二期自制移植/解包区/`（`payload.bin` 与 `OPD2513_17.0.0.105/` 共 17G）**已按可再生件删除**，只留 `payload_properties.txt`（入库件）。下面命令已改为从**仍在位的全量包 zip** 起算的完整链，别再用旧的 `解包区/…/boot.img` 直引。

```bash
# 第 0 步（新增前置）：从供体包吐 payload.bin（zip 内为未压缩存储，Size==Compressed，8.62G）
7z e -y -o"06_二期自制移植/解包区" "06_二期自制移植/供体包/OPD2513_17.0.0.105_CN01_全量包.zip" payload.bin payload_properties.txt
#   校验：sha256sum payload.bin 转 base64 必须等于 payload_properties.txt 里的 FILE_HASH
#         （实测 11-26：盘上副本 sha256 == `pq4Y5edXufA0S998…` ⇒ 与包内自校验值一致）
# 第 1 步：解出分区镜像（工具在救生包内，已在 11-26 现场用它重解 boot/vbmeta 并 cmp 逐字节一致）
"00_救生包/tools/payload-dumper-go.exe" -list "06_二期自制移植/解包区/payload.bin"          # 看分区表
"00_救生包/tools/payload-dumper-go.exe" -p boot,vendor_boot,system,vbmeta \
        -o "06_二期自制移植/解包区/OPD2513_17.0.0.105" "06_二期自制移植/解包区/payload.bin"
# 第 2 步：解 boot.img
mkbootimg --unpack_bootimg --boot_img "06_二期自制移植/解包区/OPD2513_17.0.0.105/boot.img" \
          --out 临时存档/006/boot_unpack
# 旧版工具等价写法：unpack_bootimg --boot_img <同上> --out <同上目录>
# 校验：sha256sum kernel kernel_dtb 须与上表一致
```
