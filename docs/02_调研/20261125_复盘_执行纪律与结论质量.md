## 四、结构性问题（流程，不是知识）

1. **改动跑在验证前面**：`y700_thermal_tune`、`y700_fps_unlock` 都是先装进机器再验证；被打断时留下两个未验证改动在生效。正确顺序是"改动 → 验证 → 才允许叫装上"。
2. **一次动太多变量**：同一晚动了杜比模块、温控阈值、帧率属性，重启 6+ 次，归因困难。丁方案首轮就是"配置法 + 原厂法两个创建方叠加"，数据全废。
3. **没有回滚点**：每次重启前没写"确定态快照"，导致回退后还要临时找判据。
4. **记录状态误标**：任务 #6 标题"王者 144 档—通过"，描述却是"只有 7 帧、数据无效"。这类账最危险——未来的我会信标题。（已纠正标题）
5. **工具层低级错误反复**：`su -c` 里嵌 `for/do` 至少踩 3 次、`adb push` 中文名被截断（`fix_disa`）、`/tmp` 在 Git Bash 与 Windows Python 不互通、引号嵌套把 grep 正则打坏、`7Z=` 非法变量名。每一次都在偷取证时间，而这些都能固化成模板。

## 五、做对了、要保留的

- **机器码级定位一次性死等**：手解 `.dynsym`/`.rela.plt`+`.plt` stub 反查 GOT→符号、扫 `bl`/`b` 回边判断等待是否在循环内（`临时存档/audio/dolbyfx/symdump.py`、`calltree.py`）。这是今晚唯一别人替不了的硬活。
- **离线取证成本压到极低**：ZUI 官方包 `super_N.img` 与分区一一对应且是 ext4，7-Zip 可直接抽单文件——4.7MB 拿到答案，不必解 13G。
- **开机失败前拦下变砖坑**：C17 `ro.control_privapp_permissions=enforce` + 原厂白名单缺项，照搬会起不来；补全后才继续。
- **找到今晚唯一确认的真缺口**：`use_content_detection_for_refresh_rate` 原厂 true、C17 false（其余三个帧率键两边一致）。
- **复验判据从"文件存在"改成"运行态"**：挂载数、包可见性、DAPV3 线程数、crash 计数。这条直接抓出了 `disabled`/`disable` 那个安全漏洞。

## 六、改进措施（具体、可验证）

1. **每条结论必须标注【实测】或【推断】**；推断不得进入你的裁定选项，不得写进总账。（配合已装的 `systematic-debug` 四阶段：重现→隔离→根因→验证修复）
2. **建项目专属技能**（用户选项 4 未选，但内容我已整理）：把以下硬规矩 + 脚本模板固化——
   - 禁用标记是 `disable`（另有 `remove`/`skip_mount`），`disabled` 无效；
   - 说"已回退"必须给运行态判据；
   - 移植系统 priv-app 前先查每项受限权限的 `prot=`，`signature` 而不含 `privileged` 的直接判死；
   - 改 vendor 配置必须"挂载放 post-fs-data + 整机重启"，**禁止 `ctl.restart` 温控服务**；
   - bind mount 前 `chcon` 对齐目标标签，conf 内容必须纯 ASCII 无注释；
   - 设备侧命令一律推脚本文件执行，不在 `su -c` 里嵌循环与嵌套引号；
   - 停止类指令＝本回合只出文本。
3. **一次只推进一个变量**，且每个变量配一条判据；重启前写快照行（模块标记、挂载数、关键属性）。
4. **状态词表固定**：`未做 / 已装未验证 / 验证通过 / 判死 / 已回退并复验`。禁止用"通过"描述数据无效的项。
