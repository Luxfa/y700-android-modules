# 伪装机型：风险与收益调研（供用户裁定，未实施）

> 日期：2026-11-24 17:4x　｜　性质：**纯调研，设备上零改动**　｜　触发：用户"调研一下伪装机型的风险和优势，我考虑考虑"
> 纪律：本文只给证据与推论，不代表已获授权。红线（不伪造机型身份）在用户明确改口径前仍然有效。

## 一、结论先行（三句）

1. **伪装机型解决不了"视野变小"**——视野由屏幕渲染比例决定，同比例同视野；真正的原因是**联想 ZUI 有"超广视野"（把游戏画面比例从 16:10 拉到 21:10/24:10），C17 的 ColorOS 系统层没有这个功能**。
2. 伪装机型**能影响的是画质档与帧率档**（实测本机被分到 `Grade1` / 画质 `Mid` / 渲染分辨率 75%），但在 144 帧档下 GPU 占用已 80%，**换到更高分辨率档大概率是负收益（掉帧）**。
3. 风险不为零且**不可申诉**（腾讯系封号先例集中在改机型/改帧），叠加本机现状（C17 系统层整套配置按 `OPD2511` 加载），属"为一个大概率负收益的东西，赌一个不能翻案的号"。

## 二、本机现状：我们已经"伪装"在哪一层

不是我为骗档位造的，是 **C17 移植包自带的系统身份**：

| 属性 | 当前值 | 来源 |
|---|---|---|
| `ro.product.model` / `name` | `OPD2511` | C17 原生 |
| `ro.product.brand` / `manufacturer` | `OPPO` | C17 原生 |
| `ro.product.device` | `OP6546L1` | C17 原生 |
| `ro.build.fingerprint` | `OPPO/OPD2511/OP6546L1:17/CP2A.260605.016/B.335bf99…:user/release-keys` | C17 原生 |
| `ro.soc.model` / `ro.board.platform` | `SM8850P` / `canoe` | 底层真实值，**未伪装也伪装不了**（HAL 依赖） |
| 11-24 我的模块动了什么 | `y700_identity_hygiene` 只把 `ro.product.vendor_dlkm.*` 对齐到同一套 `OPD2511`，并删联想序列号残留键 | 目的是**消除身份自相矛盾**，不是换档位 |

**关键更正（本轮新证）**：`OPD2511` **本身就是平板型号**，不是手机。C17 拆解证据 `06_二期自制移植/适配工作区/C17拆解证据/system/buildprop/my_product.build.prop` 写明：

```
ro.oplus.product.series=Pad_Mini
ro.build.characteristics=tablet
ro.build.tablet_type=mini
ro.panel.pad_compact_scale=0.7
persist.oplus.display.ogfr.exclusive=144
```

所以我此前"游戏吃到手机档位表"的说法**不准确**：游戏是按**机型库查不到 `OPD2511`** 才落到通用档（下节证据），而不是因为我们报了个手机。

## 三、游戏侧实测：LOL 到底看到了什么、给了什么档

只读取证 `192.0.2.10:5555`，导出 `/data/data/com.tencent.lolm/files/hawk_data`（1,350,492 B → `临时存档/hawk/hawk_data.json`）。可读字段：

| 键 | 值 | 含义 |
|---|---|---|
| `DevicesInfo` | **`OPPO 8Gen5`** | 腾讯给本机的机型标签：**按 SoC 兜底生成的通用名**，不是查表命中的具体型号 |
| `profileName` | **`Grade1`**（相邻 `Grade` 字段） | 性能档位分组 = **最低一档** |
| `qualityShowLevelHu` | **`Mid`** | 画质档显示为"中" |
| `resolutionLevelHu` / `fpsLevelHu` | `HZ144` / `Enable`（字段边界未逐字节解析，值待复核） | 帧率档给到 144 |
| `ro.build.fingerprint` | 完整存进 hawk | **游戏同时记录指纹**，不止记 model |
| GPU / 平台 / 屏幕 | `Adreno (TM) 840`、`canoe`、`oriScreenWidth/Height` | 多维设备指纹并存 |
| 全量检索 | **`TB323` / `Lenovo` / `Legion` 命中 0 次** | 游戏侧完全没有本机真身份的残留 |

另：`/data/data/com.tencent.lolm/files/` 下存在 `ace_shell_di.dat`、`TRI_CM_AUDIT`、`tdm_*`、`qimei`、`beacon`、`MSDK.mmap3` ⇒ **腾讯游戏安全 ACE + 设备风控 SDK 在场**。

## 四、视野的真实机制（这是本轮最有价值的一条）

1. **LOL 手游锁垂直视野、水平随比例变**：多方实测一致——"上下两边宽度都是不变的……手机是最长的，所以视野最大；平板两边稍微小点，视野也会小一点；折叠屏最小，因为宽度越像方块视野越小"。
2. **同一块屏（1904×3040，比例 1.5966）在游戏里比例没变** ⇒ 视野范围**没有理由变小**。我 17:2x 的几何取证也支持：面板原生 1904×3040、无 cutout、游戏层 bounds 铺满、两轴等比 1.3333。
3. **联想原系统的"视野大"是系统功能，不是机型档位**：联想官方与第三方评测明确——拯救者 Y700 系列有**【超广游戏视野】**，"通过改变游戏的画面显示比例获得更大视野，『超广视野』把原有 16:10 拉伸到 21:10，显示面积提升 31%；『极限视野』24:10 提升达 50%"，且已适配《英雄联盟手游》《王者荣耀》《和平精英》等。
4. 该功能的通用实现路径是公开已知、且不需要 root 的：`adb shell wm size <更长比例的分辨率>` 让游戏按带鱼屏渲染（画面上下出现黑边），用完 `wm size reset` 复原。安卓平板改超广角教程普遍如此。

**推论**：我们要的"视野回来"，正解是**改渲染比例**（可逆、零身份风险），而不是改机型。**此项仍属推论，未在本机实测**（需用户在场，我截图对比）。

## 五、伪装机型如果真的做，能得到什么

| 期望收益 | 可行性 | 本机约束 |
|---|---|---|
| 解锁更高帧率 | **无必要** | 144 档实测满帧（帧距中位 6.94ms，掉同步 1/90） |
| 渲染分辨率 75% → 更高 | 可能（换到已适配机型档） | **GPU 占用已 80%（峰 84%）**，像素 +78% 极可能把满帧打成掉帧 |
| 画质档 Mid → High/Ultra | 可能 | 同上，且 LOLM 画质主要影响特效，对"看清远处"帮助小于分辨率 |
| 视野变大 | **基本无关** | 视野由比例决定（第四节） |
| 联想宣传的"Y700 五代 LOLM 超高画质 165 帧"专门档 | 需真机串 `TB323FU`，且腾讯库里是否已上线未证 | 165 帧 + 高分辨率双升，本机 144 档已到 GPU 边缘，**大概率跑不满** |

## 六、风险清单（按严重度）

1. **账号风险，且不可翻案**：腾讯系"改机型/改帧率被封号"的公开先例集中在 CFM、王者、PUBG 系（贴吧有"改机型喜提封号""改帧被封十年"，也有"半年没事"）；结论是**统计性风险、非必然，但一旦被封基本无法申诉**。用 Zygisk/注入类改法被检测概率高于纯 `resetprop`。
2. **身份自相矛盾会被看见**：游戏同时记录 model、fingerprint、GL 串、SoC 平台、屏幕尺寸。只改 model 而 fingerprint 仍是 `OPPO/OPD2511/…`，正是"环境异常"特征；**改 fingerprint 才会自洽，但公开资料明确记载 fingerprint 与 SELinux/VINTF/HAL 不一致可致系统服务异常甚至起不来**。
3. **会动摇 C17 系统层自身**：本机大量行为按 `OPD2511` 加载（`Pad_Mini` 系列、`tablet_type=mini`、`pad_compact_scale=0.7`、`ogfr.exclusive=144`、`ro.build.version.ota=OPD2511_…`、`ro.product.authentication=26J44PC2Y949`）。改全局 model 可能让游戏空间/温控/平板模式走错分支——**这是"改一个属性影响整台机器"，与本项目"最小改动面"纪律冲突**。
4. **收益不稳定**：hawk 缓存会被服务端重下发覆盖，版本更新后档位可能打回原形，需要反复维护。
5. **可回退性好（唯一正面）**：`resetprop` 只改运行时属性，不写分区，删模块重启即复原，**不会砖**。

## 七、三条路径对比

| 路径 | 做法 | 对"视野" | 对"画质/帧率" | 风险 | 我的判断 |
|---|---|---|---|---|---|
| **甲** | 临时改渲染比例（`wm size` 拉长 → 复原），做成可开关 | **正中目标** | 无 | 最低；系统 UI 短暂变形，一条命令复原 | **推荐先做这个** |
| **乙** | 只让游戏进程看到别的 model（Zygisk 定向） | 无效 | 可能有 | **偏高**：注入进程是 ACE 检测重点 | 不建议 |
| **丙** | 全局 `resetprop` 成套改平板型号（含 fingerprint） | 无效 | 可能升分辨率 | **最高**：系统层一致性 + 封号赌注 + 大概率掉帧 | 不建议 |
| 丁 | 不动任何东西，游戏内手动拉满 + 镜头距离最大 | 无效（已拉满） | 受 `Grade1` 上限 | 零 | 现状 |

## 八、待用户裁（一次一件，不催）

**第一件该裁的是甲**：做视野 A/B 实测（改比例 → 你站泉水我截图 → 复原）。
- 做的后果：花你 1 分钟，能确定"视野到底是被比例吃掉的还是错觉"，且随时一条命令复原。
- 不做的后果：视野问题停在"机制清楚但未在本机证"，以后每次打都觉得别扭。

机型伪装（乙/丙）**建议直接放弃**：按第五、六节，它对视野无用、对画质可能是负收益，代价是账号不可申诉的风险。你若仍想试，我只在你逐次授权后动，且优先做"只读验证档位是否真的会变"，不一次性把 fingerprint 整套改掉。
