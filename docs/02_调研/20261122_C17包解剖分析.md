# 解剖分析：那个年轻人L ColorOS 17 移植包（V1.2.1）

> 总管线亲自解剖，2026-11-22。分析产物存 00_救生包/C17_ColorOS17移植包/。
> 工具：03_脚本与模块/analyze_c17.py（可复用于 088 包比对）

## 一、包形态

标准 **9008 全量包**（GeekFlashTool 生成的 rawprogram×6，对应设备 6 个 LUN：sda/sdb/sdc/sdd/sde/sdf）：
- 159 个文件，157 个刷写项 + GPT 占位（gpt_main/gpt_backup 为全零占位bin，刷机工具按"读分区表"处理，**不改设备分区布局**）
- `super.img` 20GB 精确（0x500000000），2026-11-13 构建 = ColorOS 17 移植本体（非稀疏格式，9008 整写预计 30-60 分钟）
- 无 firehose（用 088 包的）、无 README（以酷安原帖为准）、无可执行文件（干净）

## 二、关键验证结果（可信度上调依据）

| 验证点 | 结果 | 含义 |
|---|---|---|
| boot_b 内核指纹 | `Linux 6.12.30-android16-5-g1750f757fabe-ab13938768-4k`，与设备 uname **完全一致**（含构建哈希） | **boot/init_boot/vendor_boot 是联想原厂**——"保留联想底层驱动"为真 |
| boot 头 | `ANDROID!` magic 正常 | 标准启动镜像，可被常规工具处理 |
| init_boot | 8MB（0x800000 精确），含 ramdisk | 刷完 C17 后的 Magisk/KSU 修补原料就是它（已提取至包目录） |
| vbmeta_a | AVB0 magic，仅 2% 非零，sig=0 | 近空 vbmeta（等效关验证） |
| vbmeta_b | AVB0 magic，10% 非零 | 有真实描述符（ColorOS 分区 hashtree）——解锁后刷入无 AVB 障碍；**锁 BL 状态必然拒启，解锁仍是前置** |
| GPT bins | 全零占位 | 刷写时不写真实 GPT；**严禁用 edl.py/QFIL 直接写这些 bin**——用紫罗兰"读分区表"或 edl.py 的自动 GPT 处理 |
| rawprogram4 生成器 | GeekFlashTool | 与官包同构的标准格式，紫罗兰/QFIL 直接兼容 |

## 三、对我们执行链路的直接影响

1. **刷入方式锁定**：紫罗兰工具箱 9008（作者指定），或 edl.py + 088 包 firehose；**禁止裸写 gpt_main/backup bins**
2. **Root 路径明确**：C17 的 init_boot 即原厂 ZUI 内核（GKI 6.12.30），Magisk 与 KSU 均可修补；包目录已提取 `init_boot_b.img`
3. **旁路充电/游戏助手原理坐实**：作者没换底层驱动（boot/modem/tz 等原厂），联想游戏服务调用的是原厂内核接口——宣称"满血"在技术上成立
4. **刷入时长预估**：super 20GB 整写，9008 约 30-60 分钟，期间严禁断线
5. **最后安全闸**：088 包到手后做 xbl/abl/tz/uefi 哈希比对（与 C17 包内同名镜像），一致=原厂放行；不一致=停刷上报

## 四、风险余量

- rawprogram 覆盖**全部两个槽位**（a+b 完整链），刷入后两槽都是 C17；回退=用 043 回读/dd 镜像刷回 b 槽即可（a 槽本就残）
- C17 删了 OTA 组件，系统不会自更新（符合作者说明与项目锁版策略）
