## 〇、一句话

**OPD2511 = OPPO Pad 5 Pro（与本机同一颗 SM8850P）**；游戏给它的内渲是 720p，而联想自己给 Y700 的适配档是 **1080p** ⇒ **"没原版清晰"第一次有了可核查的解释**。提分辨率的官方路两条里，**"显示大小拉到最低"在 14:06 的实测只覆盖到"大厅态不变"（14:15 已收回"判死"，因四次读数全取在加载界面、对局态从未取样）**；**和平营地"分辨率提升"已于 11-25 20:1x 实测跑通**（原结论"未试"作废）：打开该开关后游戏 3D 层由 `1144x720` 变 `1720x1080`，机制＝游戏自己把 UE4 `r.MobileContentScaleFactor` 由 1.0 写到 **1.5**（720p×1.5=1080p），代价是同时砍掉 HDR/泛光/体积光/色调映射；**联想 FAQ 438819 的第二步"最小宽度改 800"本机不需要**（`wm size/density` 全程未变）。详见 `04_日志与分析/操作流水账.md` §一百零一/§一百零二 与 `02_调研/20261125_和平精英提分辨率的安全路线评估.md` §八/§九；触控采样率**已经到顶**（480Hz 实测在跑）。

## 二、720p 这个上限是谁给的（本次最大收获）

1. **引擎层是天花板的主因**：UE4 在 Android 上默认以约 720p 内渲再经 `UpscaleStage` 双线性拉伸，倍率由 DeviceProfile 的 `r.MobileContentScaleFactor` 决定；Unity 的 Fixed DPI 缩放公式上限为 1（**只能降不能升**）。出处：[Epic Device Profiles](https://docs.unrealengine.com/4.27/zh-CN/SharingAndReleasing/DeviceProfiles/)、[Epic Mobile Performance Guidelines](https://dev.epicgames.com/documentation/unreal-engine/performance-guidelines-for-mobile-devices-in-unreal-engine)、[UE4.27 Android 720p 源码分析](https://zhuanlan.zhihu.com/p/639479470)。【外部实测/文档，置信度高】
2. **同一款平板原厂给的是 1080p**：联想知识库口径——"Y700 已深度适配，**1080p 为默认且唯一启用分辨率**"（[出处](https://m.lenovo.com.cn/wiki/article-201868.html)）。【外部口径】
3. **OPPO 官方自己也承认大屏 720p 会糊**：OPPO 客服微博——"和平精英只支持 720P，一加平板 Pro 3000×2120 大屏放大后模糊"（[出处](https://m.weibo.cn/status/Os4ZBhM3M)）；OPPO Pad 5 Pro 宣传的"3.4K 超画质+144 帧"经查是**系统超分+原生帧率的组合**，不等于内渲 3.4K（[什么值得买实测](https://post.m.smzdm.com/p/axkeo8l4/)）。【外部口径+外部实测】

⇒ **所以 §十五 的候选 A/B 判掉了**：不是"移植包缺锐化"为主因，而是**这条身份线（OPPO Pad 5 Pro）本来就落在 720p 桶，而联想那条线（Y700 定制）落在 1080p 桶**。用户"原版更清晰"的记忆**与联想官方适配口径吻合**。
⇒ 但注意：这**不等于**"换回 TB323FU 身份就能拿 1080p"——联想那句是 ZUI 与腾讯的定制合作结果，是否按 `Build.MODEL` 生效**未证【推断】**，且改动触碰红线（不伪造机型身份）。

## 三、提分辨率的现实办法（按性价比排序）

### 3.1 官方渠道·零风险·优先试

- **和平营地「画面提升」里的"分辨率提升"**：官方明确 **720p → 1080p（仅安卓）**，限时 30 天、需重启游戏生效；且"**曾用第三方改客户端则不可用**"——本机从未修改客户端（我们只读），**符合资格**。另注意"游戏加速里的分辨率选项可能导致提升失败"。出处：[和平营地说明](http://www.qieyou.com/content/119736)、[细节页](https://page.sm.cn/blm/node-page-new-995/index?h=iknow.v4_3.quark.cn&id=28_a9ac1d3643261868defbdf5c7a4552b8)。【外部口径，置信度中偏高】
- **系统"显示大小/字体大小"拉到最低 → 游戏内出现更高分辨率档**：B 站同机型（Y700 五代）实测，3.4 万播放：拉到最小 → 重开游戏内的分辨率开关 → 重启游戏，**出现 1440P 选项**（原只到 720/1080），UP 主称不封号。出处：[BV1GDAWz7EVW](https://www.bilibili.com/video/BV1GDAWz7EVW)、[BV1KkAwzVE2E](https://www.bilibili.com/video/BV1KkAwzVE2E)、[BV1uww3zBEfD](https://www.bilibili.com/video/BV1uww3zBEfD)（最小宽度 814→1204）、[BV1kriKBLEDW](https://www.bilibili.com/video/BV1kriKBLEDW)（不 root 不改机型）。**反例**：[ZOL 问答](https://wap.zol.com.cn/ask/x_32347571.html)称"没反应/需重装"。【外部实测，置信度中偏高，多创作者同机型自述、无截图级数据】
  - **原理**【实测过机制】：游戏取**逻辑分辨率**定档；本机 `02_调研/20261124` 的 LOLM 实验已证 `wm size 1440x3040` 会让游戏**不重启进程**就把渲染缓冲从 2280×1428 重配到 1900×900 ⇒ 逻辑尺寸确实是档位输入之一。
  - **副作用**：全系统 UI 字号/图标变小、键位与灵敏度需重调、部分界面错位；`wm size reset` / 设置里拉回即可完全复原。
  - **【14:06 实测 → 14:15 收回"判死"，结论范围只到"大厅态"】**【实测】全程用命令做，未使唤用户。先纠正一步：`settings put system display_size -3` **写了不生效**（ColorOS 不吃这个键，密度仍 420），已 `settings delete` 收回；改用它真正背后的机制 `wm density`：

    **【收回说明（用户反证触发）】**用户实况反馈"你改的时候我真的觉得画面清晰了"。复查我自己的四次读数：420dpi×2、320dpi×1、240dpi×1，**四次全部取在"大厅/加载"界面，从未在真实对局内取样**；而 UE4 的大厅与局内**可以走两套渲染缩放**（`MobileContentScaleFactor`/`r.ScreenPercentage` 按场景配置）⇒ 数据只支持**"大厅不变"**，不支持"这条路无效"。本轮还有未控变量：13:21 游戏自行换过画面资源包；且密度下降使 `sw` 从 725dp 升到 1269dp，**同屏信息密度上升本身就会让人觉得更锐**。**⇒ 3.1 第一条状态改回"未定"，判据换成同场景 A/B（见 6.4 与流水账 §七十一）。**

    ```
    基线 420dpi（应用侧 sw725dp w1158dp）
      → wm density 320 ⇒ mGlobalConfiguration 变为 sw952dp w1520dp 320dpi（覆盖确实到达应用侧）
      → wm density 240 ⇒ sw1269dp w2027dp 240dpi（已是"拉到最低"方向）
      每档均 am force-stop + 重开游戏，共两轮；面板 renderFrameRate 90.0 正常跟随
      结果：游戏 3D 层 geomBufferSize 恒 [0 0 1144 720]、scale 恒 2.6573/2.6444 —— 一个像素都没变
      收尾：wm density reset 复核 420dpi / sw725dp（与基线逐字一致），游戏停在退出态，不留残余
    ```

    **为什么别人能出 1440P 而我们当时没出（此推论 14:15 降级为【推断】）**：那批视频靠的是游戏画面页里独立的**"分辨率"那一行**；本机 12:39 的画面页只有 **画面品质 / 帧数设置 / 画面风格 / 抗锯齿** 四组，未见"分辨率"行。**但那次截图拍于"没开营地提升、且密度未改"的条件下**，而联想官方 FAQ **438819** 给的配方是"**营地开提升 + 最小宽度改 800**"**两步同时做**（见 6.3）⇒ **"没有那一行"不能当作方法无效的证据**，只能说那一次没放出来。**本条待同场景 A/B 与营地入口共同判定。**

## 四、触控采样率：**本机已经到顶**

### 4.1 本机实测【实测，13:44】

```
/proc/HighReportRate    = "High Report Rate state 1!"        ← 高报告率已开
persist.vendor.tb323fu.touch_480hz = [1]                      ← 作者属性已置开
/proc/report_threshold  = "Report Threshold state 0!"        ← 阈值关闭=每个采样点都上报（最优态）
/proc/gesture_mode      = 1
/sys/module/nvt_36xxx/parameters/  = 参数总数 0              ← 驱动没暴露任何可调参数
/proc/nvt_fw_version    = fw_ver=16, x_num=30, y_num=48       ← Novatek NT36xxx 系，30x48 感应矩阵
输入设备                = Device 6 NVTCapacitiveTouchScreen / Device 7 NVTCapacitivePen
AOSP 原生开关            = settings system high_touch_polling_rate = null（未设）
显示模式 HIGH_TOUCH 标志  = 0 命中（联想面板驱动的模式表里根本没带这个标志）
```

⇒ **四个结论**：① 作者留的 480Hz 强制档**确实在生效**（不是"写了属性没落"）；② `report_threshold=0` 已经是最优，没有"再提高上报密度"的余量；③ **AOSP 那条标准的高触摸采样路径在本机走不通**——不是没打开，是面板模式表没声明 `HIGH_TOUCH` 标志，系统无从按档提升（这是移植固有，改要动内核 DTS，超出可行面）；④ 驱动除三个 `/proc` 节点外无可调参数，**用户侧到此为止**。

### 4.2 官方口径与社区做法【外部】

- 联想官方：Y700 五代 = **480Hz 持续 + 2640Hz 瞬时**，165Hz 面板（[Lenovo 官方产品页](https://www.lenovo.com/sg/en/p/tablets/legion-tab-series/lenovo-legion-tab-gen-5-8.8-inch-snapdragon/len103g0003)）⇒ 480Hz 是**持续档上限**，瞬时档由驱动自主触发，用户不能强制。
- 社区同类做法都有翻车记录：一加 `/proc/touchpanel/game_switch_enable` 写 1 强提 240Hz，实测"**只生效一会就回落 120**"（[出处](https://bbs.oneplus.com/thread/5765364)）；红魔 6Pro 用 `getevent -r` 量到 350–380Hz 与厂商标称不符（[出处](https://m.163.com/dy/article/G49B4PL3051180VE.html)）；流传的"解锁 144/满血采样率"模块**没有一份带 getevent 前后对比的可复核实测**（[出处](https://m.romjd.com/reviews/content/9871)），一加用户反馈付费模块"和没刷一样"。⇒ **Y700/ZUI 上 `HighReportRate` 的第三方复核数据：查不到**。
- ColorOS 侧那套 `OplusTouchNodeManager`/`SAMPLE_RATE_BY_SFREQ`/云端下发**没有公开源码或文档**；唯一间接参照是 LineageOS 的 OPLUS touch HAL 里有 `HighTouchPollingRate` 开关（[GitHub](https://github.com/LineageOS/android_hardware_oplus)）⇒ 机制本质是 vendor HAL 写驱动节点，**联想内核若无对应节点，补 HAL 也无从写起**【推断】。
- 副作用：高采样增加耗电（媒体口径 8–15%）、局部升温与降频加剧（[新浪](https://k.sina.cn/article_7879849859_1d5acf78306801lj1e.html)、[oppo之家](https://m.oppozhijia.com/wz/1080814.html)，二手/推广性质，**置信度低**）；**烧坏触控 IC 的先例：查不到**。
- 真正影响"跟手"的另一半在系统消费侧：AOSP 官方说明输入事件**按帧批处理派发**，应用要用 `getHistoricalX` 才能取到帧内全部采样点（[Android 官方](https://developer.android.google.cn/guide/topics/large-screens/input-compatibility-large-screens)）；工程师实测分析"**刷新率/FPS 不提高时盲拉采样率无收益，事件不均反而抖 UI**"（[知乎 Perfetto 解析](https://zhuanlan.zhihu.com/p/706968165)）⇒ 想更跟手，**提高游戏帧数比提高采样率更有效**，这条与第二节的"选 120/144 帧档"是同一件事。

### 4.3 想复核读数怎么测（含坑）

`getevent -tlr` 的 rate 是相邻事件间隔统计，**手指慢速移动天然读数偏低**（[坑说明](https://m.blog.csdn.net/lei7143/article/details/102467351)）；`dumpsys input` 非稳定 API 且有轮询开销；Touch Sample Rate Tester 能区分"硬件采样率 vs 应用实收率"但属个人开发者工具。**结论：读数必须以"快速划动 + 多次取最好值"为准，单次慢划不作数。**

## 六、追加（14:12）：换"一加 Pad 3 Pro 身份"值不值 —— 零收益 + 官方书面处罚证据

## 七、结案（14:26，用户裁定"分辨率没变就算了，我不想试了"）

**同场景 A/B 定论【实测，无线调试，两次都取在训练场内、同一模式、游戏内设置全程未动】**：

| | A 组 420dpi（sw725dp） | B 组 381dpi（**sw800dp，联想官方那一档**） |
|---|---|---|
| 游戏 3D 层渲染尺寸 | `geomBufferSize=[0 0 1144 720]` | **`[0 0 1144 720]`（逐字相同）** |
| 上屏放大倍率 | scale x=2.6573 y=2.6444 | **2.6573 / 2.6444（逐字相同）** |
| 面板档 | mode 4 / 90.0Hz | mode 4 / 90.0Hz |
| 实测呈现帧数 | 6 秒 554 帧 ≈ **92.3fps** | 6 秒 556 帧 ≈ **92.7fps** |
| 游戏进程 | ownerPid=12618 | ownerPid=16155（重开过，非同一进程） |

⇒ **"最小宽度改 800"这一半在本机不动渲染分辨率**（连帧数都几乎一致，说明不是降画质换来的）。联想 FAQ 438819 的另一半（**和平营地开"分辨率提升"**）**用户裁定不试**，本线就此结案，不再重开。

**对用户"改的时候觉得清晰了"的最终解释**【实测后定性】：读数不支持"分辨率上去了"；可解释的是 ① 同屏信息密度从 `sw725dp` 升到 `sw1269dp/800dp` 带来的主观锐度，② 13:21 游戏自行换过画面资源包（未控变量）。**不写成"错觉"，也不写成"确实变清晰"——只写"观感变化未被渲染尺寸证实"。**

**残余状态复核（收尾）**【实测】：`wm density reset` 后为 `Physical density: 420`、应用侧 `sw725dp w1158dp 420dpi`（与 A 组基线逐字一致）；本轮设备侧临时件残留计数 **0**；`vendor.display.use_smooth_motion=0`、`display_size=null` 均维持原厂值；未改任何游戏内设置、未改分区、未播放音频。**结论沿用 §15：本机清晰度上限 = 720p 内渲（移植固有代价），可用取舍只剩"清晰低帧 vs 流畅低画质"。**
