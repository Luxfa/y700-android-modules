## 一、一句话结论

**"稳定的模块"这条路在本机不存在**：市面上能提和平精英分辨率的 Magisk 模块，原理都是**改游戏客户端配置或伪装机型**，属腾讯安全规则明令检测的行为（最高 3650 天封禁、申诉不受理），也直接撞本项目红线"不伪造机型身份、不伪造安全校验"。

**唯一既合法又没走完的路** = 腾讯自己发的**和平营地「画面提升 → 分辨率提升」白名单**（720P→1080P，限时 30 天、开启后需重启游戏、曾用第三方改过客户端则不可用），联想官方 FAQ 把它和"开发者选项最小宽度=800"配成两步。而**本机从没装过和平营地** ⇒ 这一步从来没测过；11-25 14:26 那次"判死"只做了第二步（sw=800），是**半配方结论**，本轮已按规矩把它降级重开。

## 五、如果要推 A/B/C，动作清单与门禁（等你逐条批）

1. **装和平营地**——只能走本机在装的官方渠道（`com.heytap.market` / 游戏中心），需要你手动装并登录腾讯账号。**我不下载任何第三方 APK，也不侧载别人给的包。**
2. 营地内「营地工具 → 画面提升 → 分辨率提升」开启 → **重启游戏一次**。
3. 游戏内看 1080P 选项；**判据必须在真实对局内取 `geomBufferSize`/渲染尺寸**（技能坑 23：大厅取数会误判），并与现有 `1144x720` 基线对比。
4. 若只有开关无效，再按官方 FAQ 第二步做 `最小宽度=800`（可逆；做完必须复原并复核 `wm size/density`）。
5. C（系统"智能调节分辨率"）单独做一组 A/B：开→一局、关→一局，读渲染缓冲尺寸与帧数档，看它是提清晰度还是压画质。
6. **每步只动一个变量**；任何一步失败立即复原；全程不碰 `hawk_data`、不改任何机型键、不装改客户端的模块。

## 六、我的建议

先花你 3 分钟做 **A 的验证（装营地、看有没有"分辨率提升"入口）**——它同时回答两个悬了几天的大问题：本机 `OPD2511` 身份在腾讯白名单里到底算不算"支持设备"，以及"游戏清晰度不如原版"是不是有解。**结果无论是是否都安全**：白名单不开，就把这条线正式结案；开了但游戏里没有 1080P，再走第 4 步。

模块路线（D/E/F）我明确不建议：省下的是一次下载，代价是主力账号不可申诉的封禁风险，且踩你自己定的红线。

## 七、补测：腾讯下发的机型标签原文（决定"入口在不在"的最硬一条线索）

本机 `com.tencent.lolm` 的 `hawk_data` 早在 11-24 已导出为明文（`临时存档/hawk/hawk_data.json`，1,368,467 B；MessagePack 式二进制，非纯 JSON），本轮把字段原文重抽一遍：

| 字段 | 原文取值 | 含义 |
|---|---|---|
| `DevicesInfo` | **`OPPO 8Gen5`** | 腾讯给本机的机型标签 = **按 SoC 兜底生成的通用名，不是机型库里的具体型号** |
| `profileName` | `Grade1` | 画质档位组 = 最低档 |
| `qualityShowLevel` | `Mid` | 设置面板呈现的画质档 |
| `LODInfo` | `High…` | 模型细节档 |
| `GPUFamily` / GL | `Adreno (TM) 840` / `OpenGL ES 3.2 V@0842.31` | GPU 识别正确（SM8850 系列） |
| `resolutionLevel` | `HZ144Z`（编码 token，本地不可解） | 分辨率档由服务端加密下发 |
| `fpsLevel` | `Enable`（后接键名，值不可解） | 帧率档同上 |

**判读**：

1. 【实测·LOLM 侧】本机在腾讯体系里的身份标签是 **SoC 兜底名**，说明 **没有命中它的机型库具体条目**。
2. 【推断，不得当依据】"画面提升/分辨率提升"这类白名单功能普遍按机型库下发 ⇒ 对本机开放的**先验概率偏低**。但和平精英自身那份 `hawk_data` 只有 3849 B 且为密文（头部 `c1 02 7b 4d …`，strings 只露 `Qualcomm`），**无法据此断言**，只能装营地看入口。
3. 【官方文档】豆特那份营地 FAQ 列了资格门槛：**当前赛季经典模式对局 ≥20 局、申请当日前一周至少 2 天登录、前一个月至少 8 天登录、良好安全记录**，并且明写"**若操作后仍无法体验，请耐心等待未来扩大可用机型的范围**" ⇒ 官方承认机型范围有限，不是全员开放。[豆特营地页](https://m.duoteyx.com/game/3540.html)
4. 【官方文档】另一份营地说明补一条关键约束：**"只有当天登录营地方可激活游戏内该工具的功能"** ⇒ 装了还要当天登录一次，不是装完就永久生效。[acura 营地页](https://m.acura.com.cn/soft/25471.html)

**结论不变但依据更硬**：安全路线只有营地白名单一条；能否开放**只能靠装营地看入口**定论，成本 2 分钟、零风险（不登录也不改任何本机文件，卸载即回原状）。若入口不在或开了无效，本线以"腾讯机型库未命中本机"结案，比 14:26 那次"我不想试了"的口径更站得住。

## 八、结局：方案 A 实测跑通（2026-11-25 20:0x 定档）

用户打开**和平营地「画面提升」→ 分辨率提升**（本机该页共三颗开关：画质提升 / 分辨率提升 / 功耗自适应）后，游戏 3D 层实测：

- `geomBufferSize` `1144x720` → **`1720x1080`**（渲染像素 823,680 → 1,857,600，**2.26 倍**）
- `toDisplayTransform` 放大倍率 2.6573/2.6444 → **1.7674/1.7630**（糊上屏的程度明显减轻）
- ~~`renderRate=144.00 Hz`、合成 144.8fps~~ ⇒ **11-25 20:1x 更正作废**：该次采样时用户正在拨开关、场景归属不明；五轮受控 A/B 显示大厅态恒 ~88–91fps，`renderRate` 只随前台场景变（60/90/165Hz）。帧档是否被抬高**仍未证**，见 §九
- `wm size/density` 未变 ⇒ 本文 §五 里"最小宽度 800"那半步**本机不需要**
- 关闭后回落到 1144x720 ⇒ 开关可控，非一次性写死

**结论**：本文判断成立——**只有方案 A（官方营地白名单）是安全且有效的**；D/E/F（改客户端 ini、伪装机型、动 `hawk_data`）一条都不用碰。本文 §六 的"建议"与 §七 的"白名单开放概率偏低【推断】"由实测取代。

**长期约束（防日后误判）**：权益限时 30 天、当天登录营地才激活；到期后回落 720p **不是移植包坏了**，按 §八 复开步骤重开即可。


## 九、五轮受控 A/B 定档（2026-11-25 19:4x~20:1x，取代本文前面所有"概率/推测"性表述）

完整数据与差异分析在 `04_日志与分析/操作流水账.md` §一百零一，此处只留对本方案选择的三条硬结论：

1. **生效的是「分辨率提升」这颗开关**：只开`画质提升`时渲染尺寸纹丝不动（1144x720），加上`分辨率提升`立刻变 1720x1080（像素 2.26 倍、放大倍率 2.65→1.77）。⇒ 以后要提清晰度，**只需这一颗**。
2. **系统侧零改动**：五轮 `diff` 显示属性、settings、温控、SELinux、刷新率策略、游戏版本全部无实质差异 ⇒ 营地不需要 root/模块/分区改动，**方案 A 与本项目红线完全兼容**（未改客户端、未伪装身份、未动 `hawk_data`）。
3. **判据只有一个**：`dumpsys SurfaceFlinger` 游戏层的 `geomBufferSize`。`renderRate`（随前台场景浮动）与 `hawk_data` 大小（运行时自涨，同配置 2 分钟 69K→102K）**都不可作判据**——本文前面把 `hawk_data` 当"营地落配置"的说法已降级为附带观察。

4. **机制已查到底**（流水账 §一百零二）：`分辨率提升` = 把 UE4 `r.MobileContentScaleFactor` 从 1.0 拉到 **1.5**（720p×1.5=1080p，与实测尺寸三处互证）；同时**砍后处理**——`r.MobileHDR`/`r.BloomQuality`/`r.LightShaftQuality`/`r.Mobile.TonemapperFilm`/`r.Mobile.AlwaysResolveDepth` 全 1→0、`SceneColorFormat` 2→0、`ACESStyle` 0→1。⇒ 本项目原本担心的"第三方提分辨率必改客户端"在这条官方路上**不存在**：改的只是游戏自己沙盒里的 `UserCustom.ini` 与 `playerprefs.sav`，双向可逆、无残留。

**仍未证**：帧率档是否被抬高（需在对局内用同一把尺复采）；`功耗自适应` 的独立作用（怀疑就是上面那几项后处理被砍的来源，需"只开分辨率、不开功耗自适应"的一次取样）；`画质提升` 除 `art_quality_improve` 位外还改了什么。
