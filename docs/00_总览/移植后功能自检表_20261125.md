# 移植后功能自检表（防"以为已通"）

建立：2026-11-25 12:2x ｜ 整理：hutao ｜ 任务 #20
**为什么必须有这张表**：深挖两轮证实公开层**没有**"五代 + ColorOS 17"的作者说明书与已知问题清单（`02_调研/20261125_论坛挖宝结论表.md` 6.0），我们没有任何外部答案可抄；而本项目已经多次发生"看起来通了其实没通"（`disable` 标记写错导致危险模块复活、bind mount 静默不加载、性能策略"重启后拒绝计数 0"被当作生效证据）。

## 使用规则

1. **状态词表固定，只能用这六个**：
   `✅实测通过` / `⬜未检` / `⚠️已知缺陷-移植固有` / `🚫不适用-本机无此硬件` / `⛔判死不修` / `🔶待用户实况`
2. **"实测通过"必须写清判据与出处**（文件+行号或相位号），写不出判据的一律降为 `⬜未检`。
3. **`🔶待用户实况` 是合法状态**——凡主观体验（流畅、跟手、声音好不好）只有用户能判，不许我替用户宣布通过。
4. **`⬜未检` 不等于"没问题"**。每次新装/卸载模块、每次改动 vendor 配置后，**受影响的行必须回到 `⬜未检` 重测**，不许沿用旧 ✅。
5. **稳定性结论必须覆盖至少两类真实场景**（长播放 + 频繁切换），单场景通过不得填 ✅。
6. 表内引用的每一项"实测"，复核方法见 `04_日志与分析/打通取证_20261125_*.txt` 与对应相位记录。

**基线**：系统=C17 成套（联想 vendor + ColorOS 17 系统层，身份 OPD2511）；模块在装 8 个（2 个带 `disable`）；BL 锁着、root 走 9008 写 init_boot。
